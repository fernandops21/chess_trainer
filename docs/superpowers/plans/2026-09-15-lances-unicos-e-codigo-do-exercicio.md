# Exercício continua enquanto o lance for único; código curto do exercício — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** (1) O exercício dos próprios erros não termina no ganho de material: ele continua enquanto o próximo lance do aluno for **único** (a segunda linha da engine fica bem abaixo da primeira), sem teto de lances, e para quando há dois lances bons, no mate ou no fim da partida. (2) Um job "estender exercícios" aplica a regra aos exercícios existentes mantendo o histórico de repetição. (3) Cada exercício mostra um código curto (`#ff466803`) copiável e pode ser aberto por ele.

**Aprovado em conversa (2026-09-15):** "não adianta ganhar material se você perde; o ganho só se justifica se depois você acha a defesa ou o próximo ataque"; sem teto de lances. Simulação no exercício `ff466803` (pretas): solução hoje `Be6 Kb8 Bxb3`; com a regra: `… 41.Bf3 Bd5! 42.Bxd5 e2! 43.a7 e1=Q 44.a8=Q Qe5+ 45.Kc8` e para (Qe8+ e Qxd5 empatam em +4.89).

## Tasks

### Task 1 — backend: extensão por lances únicos no gerador
Files: `backend/chess_trainer/core/puzzles/generator.py`, `backend/chess_trainer/config.py` (`AppSettings.unique_gap_cp: int = 150` → `PuzzleConfig.unique_gap_cp`), `backend/chess_trainer/api/schemas.py` (`SettingsOut/SettingsIn.unique_gap_cp`), tests `backend/tests/test_generator.py` (ou o arquivo dos testes do gerador com engine dublê), `test_config.py`, `test_api_system.py`; frontend pequeno: `frontend/src/api/types.ts`, `frontend/src/pages/SettingsPage.tsx` (campo numérico "lance único: distância mínima para a 2ª linha (cp)" com limites 50–1000), `frontend/tests/fixtures/settings.ts` e testes que listam o `Settings` inteiro.
Regra (`extend_unique_line(board_after_solution, engine, cfg, solver) -> list[SolutionMove]`, função pura chamada por `_materializing_line` antes de devolver o `_draft` de `material_gain`; **não** se aplica a `end_reason == "mate"`):
1. Se é a vez do adversário: `engine.analyse(board, cfg.depth, multipv=1, max_seconds=cfg.search_seconds)`; sem linha ou posição terminal → para; senão aplica `lines[0].move` como `SolutionMove(by="engine")` e segue.
2. Na vez do aluno: `engine.analyse(board, cfg.depth, multipv=3, max_seconds=cfg.search_seconds)`; terminal/sem linha → para. `gap = lines[0].score - lines[1].score` (só uma linha → gap infinito). Se `gap < cfg.unique_gap_cp` → para (dois lances bons: técnica). Se `lines[0].score < cfg.min_solver_eval_cp` → para (o "único" já não ganha; a solução fica como estava até aqui). Senão aplica `lines[0].move` como `SolutionMove(by="solver", alternatives=[])` e segue.
3. Sem teto de lances **por regra**; um limite interno de segurança de 60 meios-lances (`MAX_EXTENSION_PLIES`) só para não entrar em laço (comentar que é proteção, não regra), e em mate a linha termina com o lance que dá mate.
4. A solução nunca termina com lance do adversário: se o laço parou logo depois de um `engine`, esse último lance é descartado.
5. `solver_moves` recalculado; `end_reason` continua `material_gain`.
Testes com engine dublê roteirizada por FEN: linha estendida em 2 lances únicos e parada quando o gap cai; parada em mate (`terminal`); parada quando o melhor cai abaixo de `min_solver_eval_cp`; último lance do adversário descartado; `unique_gap_cp` respeitado; puzzle de mate não estendido; `generate_avoid` também estende. Commit `feat(puzzles): o exercício continua enquanto o lance do aluno for único`.
